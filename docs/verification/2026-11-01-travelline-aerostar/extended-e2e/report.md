## Повторяемость и границы

Временный harness находится вне репозитория. Регулярный scheduler фиксирует
одного взрослого и LOS 1/2; диагностический план использовал существующий
BuildPlans для run identity и PlanRun для явных сценариев 2 взрослых, LOS 1/2/3.
Исполнение, HTTP limiter, leases/fencing, нормализация и сохранение — штатный RunQueued.
Режим MaxAttempts=1 ограничивал live-запросы; повторов из-за ошибок не потребовалось.

Первый подготовительный запуск завершился на локальной проверке claim options
из-за отсутствующего lease owner во временном harness: 0 HTTP-запросов. После
задания owner выполнен единственный live-прогон из 9 запросов. Продуктовый код
не изменялся. Это дефект harness, а не TravelLine-адаптера.
