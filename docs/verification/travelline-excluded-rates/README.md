# Проверка 167 исключённых предложений TravelLine — 05.11.2026

Исследованы три тарифа из [исключений полного сбора 03.11](../travelline-full-collection/exclusions.csv). Все 167 исторических предложений найдены в сохранённых исходных JSON. Причина исключения — фиксированный allowlist, **не дефект парсера**. Ветка основана на `dev` после merge #54 (`2d7e174`). Production-код, конфигурации, `enabled`, PostgreSQL и CSV не изменены; новый массовый сбор не выполнялся.

## Вывод и рекомендация

Публичность подтверждена **на уровне анонимно отображаемого предложения**, а не завершённого бронирования. Во всех шести сопоставленных карточках совпали hotel/category/rate ID, 1 взрослый, 1 номер, LOS=1, RUB и полная цена API → XHR формы → DOM. Авторизация и промокод не использовались. Заказ, корзина, ввод данных гостя и оплата не выполнялись; возможность завершения заказа без дополнительных условий **не подтверждена**.

**Ответы по 167 предложениям:**

1. Потенциально публичными являются все **167** исторических offers трёх тарифов: их условия доступны анонимно и каждый тариф подтверждён в DOM на двух будущих датах. Это перенос классификации тарифа на исторический snapshot, не повторная DOM-проверка всех 167 строк. Для нынешнего несегментированного сравнения **48 — кандидаты после согласования**, **119 — не добавлять вместе с обычными тарифами**. Безусловно рекомендованных обычных `standard` offers — **0**.
2. **119 пакетных** (56 + 63) и **48 условных/специальных**. `promo=false` у всех 167 — самостоятельным доказательством публичности это не считалось.
3. Оба пакета продолжать исключать из основного сравнения. «Горящее» тоже остаётся выключенным до согласования политики; доказательств обязательного членства/промокода на просмотренном шаге нет.
4. Да, тарифы могут изменить минимум без сохранения сопоставимых условий. В историческом snapshot «Горящее» ниже разрешённого минимума той же category/guest composition в **13 из 48** offer-строк, «Пикник» — в **22 из 56**, романтический пакет — в **0 из 63**. Это сравнение с реально настроенным allowlist, **не с гарантированно чистым room-only benchmark**: в нём уже есть специальные тарифы. Нулевое число снижений у романтического пакета не доказывает будущую сопоставимость.
5. Технически текущая модель сохраняет ID/название тарифа, цену и валюту; одного allowlist достаточно для разрешения сбора «Горящего», если его условия приняты. Но `rates[].enabled` и offer-модель не содержат отдельной классификации `standard/package/conditional`, питания и возвратности. Простое включение пакетов не обеспечивает раздельного сравнения. Для их автоматического отделения потребуется отдельное последующее решение о классификации/фильтрации; в этом исследовании архитектура не расширялась.

## Live API и анонимная форма

Сценарий: 1 взрослый, 1 номер, LOS=1, без детей/промокода, ru/RUB. Основные будущие даты из `exclusions.csv`: **07/14.11 для обоих тарифов МонАрха**, **13/20.11 для Петровского**. Дополнительно один availability МонАрха 13.11 показывает изменение доступности «Горящего»; это не одна из двух исторически положительных дат этого тарифа.

Выполнены **9 прямых GET**: 2 `hotel_info`, 5 `hotel_availability`, 2 scoped `rate_plan_booking_rules`. Все HTTP 200, `error_code` отсутствует. Точные URL, query, UTC timestamps, размер и SHA-256: [live-manifest.json](live-manifest.json). Без body, OAuth, пользовательских cookies и токенов. Ответы спроецированы в [live-api.json](live-api.json).

- `GET /ApiWebDistribution/BookingForm/hotel_info`: `hotels[0].code`, `language=ru-ru`, `audience=BookingForm`.
- `GET /ApiWebDistribution/BookingForm/hotel_availability`: `criterions[0].hotels[0].code`, `criterions[0].adults=1`, `criterions[0].dates=checkin;checkout`, `include_all_placements=false`, `include_promo_restricted=true`, `include_rates=true`, `include_transfers=true`, язык/audience.
- `GET /ApiWebDistribution/AvailabilityCalendar/rate_plan_booking_rules`: `hotel`, `rate_plans[i].code`, `start_date`, `end_date`, audience. Диапазоны ограничены 07–13.11 для МонАрха и 13–20.11 для Петровского; calendar rules на 14.11 отдельно не запрашивались.

Сам выбор даты/категории и DOM тарифов проверены в соответствующей TravelLine-форме (`providerId=17249` / `5787`) в новых неавторизованных Chrome contexts. Кнопка категории открывала только список «Выберите тариф»; кнопки выбора тарифа, корзины и заказа **не нажимались**.

Первая загрузка страниц иногда не завершала JS-рендер: пустой DOM не объявлялся отсутствием тарифа. Для исследования понадобились initial category view, room-details view и затем rate-list view. На Петровском 13.11 rate-list загрузился после одного ограниченного повтора. Результаты, включая неудачные рендеры, сохранены: [первый просмотр](browser-evidence.json), [детали категорий](browser-details-evidence.json), [тарифы](browser-rates-evidence.json), [повтор](browser-retry-evidence.json). Fonts/images/media блокировались на повторных просмотрах; ответы availability не подменялись fixtures. API-старты ограничивались общей последовательной gate с интервалом не менее 1,05 с; скрытые XHR формы также проходили через неё.

Зарегистрировано **76 публичных browser API GET** (включая settings/common/calendar) и 9 прямых GET, все записанные ответы HTTP 200. Статические ресурсы, загрузки официальных страниц и заблокированные запросы в эти числа не входят. Это ограниченная проверка пяти hotel/date, а не новый 61-дневный сбор.

## Условия и неопределённость

- **816956:** live DOM 07.11 показывает завтрак, бесплатную отмену до 06.11 23:59, «Без предоплаты», total 10 540. Описание запрещает изменение проживания. Исторический room_stay для 03.11 имеет `free_cancellation=false` и текст о невозврате после предоплаты; у 46 других исторических stays flag true. Нельзя считать тариф одинаково возвратным на всех датах. На дополнительной дате 13.11 offers исчезли; scoped rule содержит `min_los_arrival=2`, совместимое с отсутствием LOS=1. 14.11 LOS=1 снова продаётся.
- **951554:** live DOM — «Условия отмены», «Без предоплаты». API одновременно содержит `free_cancellation=false`/penalty «в любое время — первые сутки» и описание «бесплатно до 16:00 дня заезда». Противоречие сохранено; точная применимая отмена требует разъяснения отеля/TravelLine. Пакетность подтверждается самим описанием услуг, а не предположением по названию.
- **633705:** live API и DOM предлагают пакет даже при 1 взрослом, хотя текст включает услуги на двоих. Это не основание менять guests или делить total пополам. API: бесплатная отмена до 10.11 15:00 для заезда 13.11 и до 17.11 15:00 для заезда 20.11, затем 100% предоплаты; описание требует предоплату за 72 ч. DOM показывает «Без предоплаты», а availability допускает guarantee-вариант наряду с card/SBP. Это не доказательство отсутствия последующей обязанности внести платёж: способ обеспечения/финальные условия без заказа не проверены.

`public_confirmed` относится к анонимной видимости и совпадению опубликованной цены. Применимость всех услуг, окончательные payment/cancellation terms, завершение бронирования и будущая доступность вне проверенных дат не гарантируются. `restricted` не установлен ни для одного тарифа; необходимость авторизации/промокода на просмотренных карточках не обнаружена.

## Безопасность и проверки

JSON — безопасные публичные проекции: удалены guest/session refs, cookies/headers, contacts, tracking и нерелевантные HTML/ссылки. Описания тарифов и отмены преобразованы в текст; не публикуются полные DOM и исходные bodies. SHA-256 в manifest относится к **исходному** body; это не checksum санитизированной проекции. Нет аккаунтов, бронирований, персональных данных или обращения к production DB/Диску.

Offline-воспроизведение: `python3 docs/verification/travelline-excluded-rates/audit.py`. Скрипт проверяет все 167 строк и даты против прежних exclusions, статусы HTTP, guest/date/currency, quota references, шесть DOM/API-сопоставлений и запрещённые поля evidence. Проверки и checksums файлов: [checks.json](checks.json). Production-тесты не заменяют доказательства публичности; повторный live-прогон для audit не нужен.
