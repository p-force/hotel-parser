## Сверка API → Parse → normalization → PostgreSQL → CSV

Для каждой из 305 попыток сохранены исходные metadata и availability; audit независимо построил разрешённые ключи `(category, placement variant, rate)` с ценой, валютой и quota через response-local RPH. Они сопоставлены с результатом `Parse`. Категории, площади, даты, взрослые, структура total, placements и отношения quotas проверены отдельно. Некорректных JSON, source errors/warnings/availability diagnostics, новых unsupported kinds, multi-room/rate ambiguities и расхождений raw → Parse **не обнаружено**.

Затем результат `Parse` и нормализованные категории сопоставлены с чтением committed attempts/observations/offers из PostgreSQL. Проверены все 7972 цены/валюты/квоты и 2379 статусов/остатков. После этого сверены **8280 строк данных** пяти CSV (35 колонок): 7972 offer-строки + 308 категорий без offers. `NULL` сохранён пустой ячейкой, не нулём. Категории без offers не исчезли. Квоты вариантов/тарифов не складывались. Дополнительно все **35 колонок × 8280 строк = 289800 ячеек** сверены с committed readback: timestamps сравнивались как UTC instants, цены и площади — точными Decimal. ## Намеренно исключённые тарифы

Источник вернул **10773 room stays**: 7972 разрешённых offers сохранены; **2801** исключён тарифной политикой. Это отдельная причина фильтрации, не ошибка парсера и не доказательство отсутствия категории.

- **2634** записей — BONUS/промо: 2272 AZIMUT Bonus и 362 «Привилегия» Советского (`131363`, promo); последние 362 вообще не содержат полной цены.
- **167** записей с ценой — тарифы вне зафиксированного allowlist: МонАрх `816956` (48), `951554` (56), Петровский `633705` (63). Они были disabled ещё до этого прогона; allowlist не расширялся посреди эксперимента.
- Ни один unknown не объясняется только фильтрацией тарифа: во всех 308 случаях категории не было среди raw room stays, либо raw список был пустым.

Названия, частоты и точные даты всех 11 исключённых тарифов: [exclusions.csv](exclusions.csv). Наличие анонимной цены вне allowlist здесь зафиксировано отдельно; такие строки не объявлены разрешёнными обычными ценами и не добавлены в итоговые CSV.

UI и calendar получены после основного сбора: они подтверждают представительное публичное поведение, а не исторический snapshot каждой из 61 даты. Подробная физическая причина закрытия продаж и полнота всех ограничений остаются неизвестными.

## Безопасность evidence и воспроизведение

В репозитории сохранены полные итоговые CSV, таблицы всех сценариев/категорий, raw quote projection, HTTP timestamps/checksums и безопасные JSON-примеры для каждой группы. Полные исходные HTTP тела не публикуются: из samples удалены contact info, guest/session IDs, cookies, service/cancellation HTML. Samples сохраняют поля, которые читает адаптер: identities, kinds, площади, dates, guests, placements, totals, rate IDs/promo и quota/RPH. SHA-256 исходного body и его проекции различаются намеренно и зафиксированы в [evidence/index.json](evidence/index.json).

Основной прогон использовал временный диагностический harness на штатных Go API, без отдельной очереди/scheduler. `registry.json` — отдельная конфигурация, не основной список групп. Чтобы проверить уже полученные данные, достаточно offline `audit.py`; новый live plan запускать для этого не требуется. Если продолжать выполнение через CLI, использовать ту же схему/slot и `resume`, с YANDEX_DISK_TOKEN отсутствующим. Запуск default `tick` из основного registry к этой диагностике не относится.
