не опрашивались. Проверены конфиги, сохранённые ответы/fixtures, парсеры, persistence,
CSV и официальные опубликованные материалы. Данные поискового индекса не означают
повторной проверки актуальности документа у владельца отеля.

`rooms_quantity`, число тарифов и максимальные наблюдения этим документом не являются.

## Матрица причин

| Bnovo | sales_closed | Видимость/disabled/недоступность | Нет | Явный код закрытия продаж и его область действия |
| Bnovo | no_rate | Пустые/неполные тарифные блоки и предупреждения парсера | Нет | Явное подтверждение отсутствия тарифа для конкретного сценария |
| Bnovo | technical_error | HTTP/status, timeout/transport/parse и другие известные коды | Да, на уровне сценария | Ничего для существующих кодов; это не причина уровня каждой категории |

| TravelLine | minimum_stay | `errors`, `warnings`, `availability_result`; подтверждённого кода ограничения нет | Нет | Реальный ответ с документированной связью к категории/тарифу и датам |
| TravelLine | sales_closed | Те же диагностические массивы, иногда отсутствие предложения | Нет | Подтверждённый restriction code, scope и сценарий |
| TravelLine | no_rate | Не выбран allowlist, промо исключено или нет предложения — различные ситуации | Нет | Явный source code; исключение политикой не равно отсутствию тарифа у отеля |
| TravelLine | technical_error | HTTP/status, transport/timeout/parse коды | Да, на уровне сценария | `source_error` оставлен unknown: API rejection может быть бизнес-ошибкой |

Проверенные сохранённые TravelLine `availability_result` пусты. Синтетическое
`errors: [{error_code:450,message:"minimum stay"}]` из unit-теста не является
доказательством значения реального кода 450. Не добавлено распознавание английских
слов/произвольных warning codes как бизнес-причин.

### Что теряется

- Bnovo: `parser.go` сохраняет совпавший текст в `CategoryAvailability.Reason`;
  `collect/persistence.go` сохраняет флаги и предупреждения, но не этот текст.
  Формулировка подтверждает недоступность на даты, но не различает пять причин.
  Другие сообщения `.tariff__nodates` могут не попадать даже в Reason.
- TravelLine: `parser.go` сводит непустые warnings/availability_result к
  `source_diagnostics`; source errors возвращаются как `source_error`.
  Детали, коды и привязки исходных массивов не входят в доменную модель.
- Общий persistence хранит `Warning.Code/Context`, но не Message; ошибки — Code и
  Retryable. Свободный текст источника намеренно не записывается. CSV v3 сохраняет
  warning-массивы раздельно на уровне попытки и категории, включая context.

Восстановить потерянные детали старых ответов из БД невозможно. Парсеры не изменены:
без проверенного формата restriction добавлять новые предположительные коды нельзя.
Для будущей поддержки нужен безопасный реальный пример и точное правило привязки;
затем можно добавить типизированные evidence, не архивируя произвольный HTML/PII.

## Реализованный отдельный контракт

Формат `availability-diagnostics/v1`, JSON, чтение **завершённого run** из PostgreSQL.
Основной CSV v3 остаётся ровно 35 колонок. Отчёт не отправляется автоматически на Диск.

```sh
go run ./cmd/collection diagnostics --groups configs/groups.json \
  --group-id arena33 --run-id '<UUID завершённого run>' > diagnostics.json
```

Используется существующий `HOTEL_PARSER_DATABASE_URL`; токен Диска не нужен.
Перед первым использованием новой версии применяется штатная миграция `0007`.
CLI открывает service/клиенты, но не вызывает Collect, HTTP, Runner, plan или delivery.
Go API: `collect.WriteRunDiagnostics(ctx, store, runID, writer)`;
чистая классификация: `collect.DiagnoseRun(storage.RunDiagnosticData)`.

- `data`: run, сохранённый inventory snapshot (либо null), job, точный source/origin/property/scenario, даты/LOS/гости/children,
  финальная сохранённая попытка (либо null), timestamp, warning code/context,
  observations, варианты, тарифы, исходные квоты и политика отбора. Lease credentials
  исключены. Вложенные storage-модели используют исходные имена Go-полей (`Scenario`,
  `Source`, `CheckIn`, `Warnings`); поля оболочки и findings — snake_case.
- `findings`: `job_id`, необязательные `category_id`, `rate_id`, `scope`
  (`scenario/category/rate`), `code`, `cause`, `verdict`, `evidence`.
- `evidence`: attempt ID, HTTP status, раздельные warnings, nullable available и
  флаги, ссылки на сравниваемые job/attempt и вариант. NULL/false/0 не смешиваются.
- `verdict`: `confirmed` только для известных технических кодов; `observation`
  для явной недоступности без доказанной причины и различий LOS; `conflict` при
  конфликтующих флагах/предложениях; `unknown` при недостатке фактов.
- `cause`: пока `technical_error` либо `unknown`. Наличие кода `minimum_stay` в
  произвольном предупреждении не делает его подтверждённой причиной.
- Несколько findings не исключают друг друга. Техническая ошибка остаётся на
  уровне сценария; категория и конкретный тариф не получают её автоматически.

### LOS и сопоставимость

Сравнение только внутри одного run: одинаковые отель, source/origin/public ID,
заезд, adults/rooms/children/language. Выезд должен соответствовать LOS. Короткий
сценарий LOS=1: наблюдение есть, нет ни offers, ни HasOffers. Длинный LOS=2/3:
есть видимый, не disabled тариф с ценой/валютой и подходящим вариантом. Действующее
правило `AccommodationVariant.MatchesAdults` Bnovo переиспользовано.

Для обеих попыток требуется одинаковый **сохранённый** snapshot тарифной политики:
TravelLine allowlist (длинный тариф должен в неё входить), Bnovo all_visible.
`0007` добавляет только immutable `attempt_selection_policy`; запись атомарна с
SaveAttempt, включена в payload hash/fencing, nil пропускается для совместимости
со старыми payload. Старые попытки не дополняются сегодняшней конфигурацией.

Конфликты, пропавшие observations, failed, неизвестные глобальные предупреждения
и отсутствие политики блокируют LOS-сравнение. Partial допускается только с
известными предупреждениями о неподтверждённом количестве/доступности; наличие
цены не объявляет количество известным. Для консервативности предупреждение о
дефекте иной категории также может заблокировать сравнение.

`duration_dependent_availability` означает: в сравниваемом тарифном наборе
категория без предложения на одну ночь имела предложение указанного тарифа
на две/три. Отсутствие тарифного блока на коротком LOS не доказывает причину на
уровне тарифа. Это **не minimum_stay**: возможны иные ограничения или изменение
доступности между timestamps запросов. Факты и обе попытки остаются в отчёте.
Ничего не суммируется, цена не пересчитывается и не переносится между LOS.

Незавершённый run возвращает ErrIncomplete до записи JSON. Отсутствие попытки или
observation не превращается в успех/ноль. Отчёт восстанавливается после рестарта
без HTTP, локального CSV cache и runner lock. Он отражает финальные попытки;
предыдущие retry остаются в append-only истории, но не выдаются за финальный факт.
