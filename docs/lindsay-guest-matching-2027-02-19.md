# Lindsay: проверка сценариев на 1/2 взрослых

Заезд 19.02.2027, выезд 20.02.2027, LOS=1, язык ru, без детей.

Проверено: 2026-10-26T09:39:51Z. По одному запросу через NewClient/Collect на сценарий, без повторов.

`Adults` варианта извлекается из `.guest-list`: это характеристика тарифной строки, а не требование равенства числу гостей запроса. Для меньшего запроса дополнительно требуется явный `tr[data-available=1]`; без этого признака остаётся точное сопоставление. `select[data-available]` — отдельный количественный сигнал. Флаг родительского `data-available-for-guests` сохраняется без интерпретации: он бывает 0 у бронируемых строк семейной категории и студии. Цены сохраняются отдельно по запросу, варианту и тарифу; не переносятся между сценариями.

Основание для изменения: в ответе на фактический `adults=1` присутствуют `.guest-list`
с двумя значками, `tr[data-available="1"]`, активный селектор и кнопка «Забронировать».
Поэтому равенство числа значков и числа взрослых запроса не является обязательным.
Обратный вывод о максимальной вместимости категории не делается. Строки без явного
подтверждения не начинают подходить меньшему запросу только из-за числа значков.
В [клиентском JS Bnovo](https://reservationsteps.ru/dist/js/main-cdb7174acf.js)
обработчик `.rows-toggle` показывает и скрывает строки `tr[data-available="0"]`;
это флаг строки интерфейса, его нельзя интерпретировать как нулевой остаток.
При его отсутствии сохраняется прежнее точное сопоставление для других страниц Bnovo.
