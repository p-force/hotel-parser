# Bnovo: Тета Измайлово и Новое Измайлово

Исследование 09.11.2026, связанная задача [#58](https://github.com/p-force/hotel-parser/issues/58). Проверены только LOS=1, один взрослый, без детей, один номер, язык `ru`. Конфигурации, регулярный сбор и production-код не изменены.

**Результат:** обе опубликованные формы работают с текущими `Client.Collect()` и `NormalizeCategoryStock()` без изменений. Найдены два разных UID и непересекающиеся наборы из двух и шести категорий. UID Нового Измайлова подтверждён ссылкой с основного сайта. У Теты работоспособность кандидата подтверждена, но его актуальную привязку к основному сайту подтвердить не удалось из-за недоступности сайта из проверяющего окружения.

Основные сайты напрямую через Python `urllib` завершились `URLError: timed out`, без полученного HTTP-статуса. Chrome: `page.goto: Timeout 20000ms exceeded`, без загруженного документа. То же относится к прямому доступу к `/booking/` Нового Измайлова. Точные времена и ошибки: [sites.json](sites.json), [browser-sites.json](browser-sites.json). Поле `status=0` означает отсутствие HTTP-ответа, а не ответ сервера с кодом 0.

Через web text retrieval основной сайт Нового Измайлова и `/booking/` доступны: получена ссылка на указанный UID, её переход сохраняет этот UID. Дополнительный редирект на другой объект не наблюдался. Для основного сайта Теты этот способ также не дал содержимого; его фактический booking URL/цепочка редиректов остаются неизвестными. На [старом сайте Теты](https://teta-izmaylovo.tb.ru/) ссылка ведёт на кандидат `64a67259-…`. Это вспомогательное подтверждение, а не доказательство актуальной настройки нового сайта. Фактические извлечённые поля: [web-evidence.json](web-evidence.json); это проекция содержимого, не сохранённый исходный DOM сайтов.

Одинаковый адрес не делает формы одним объектом: разные UID, названия и RoomType ID. Ни одну форму нельзя объединить с другой одним вымышленным `source.property_id`. Не установлено, полностью ли отсутствует пересечение их физического номерного фонда.

## Сигналы остатков и проверка парсера

Для всех 78 предложений `select[data-available]` совпадает с максимальным положительным разрешённым `<option>`. Опции содержат 0 (ничего не выбрано) и последовательность `1..N`; нулевой выбор не означает отсутствия мест. Атрибуты `min` и `max` у select отсутствуют. `tr[data-available="1"]` подтверждает доступность строки, это **не** количество номеров. `SelectDisabled=false`, `data-available-for-guests="1"`. Между тарифами категории количества совпадают, суммы не используются.

Сверка с DOM выполнена независимо от Go-парсера через Chrome с отключённым JS и блокировкой всех сетевых запросов. В [html-signals.json](html-signals.json) сохранены безопасные проекции реальных узлов: названия, описание, атрибуты карточек/тарифов/строк/select, `.guest-list`, исходные цены и options. Полный HTML не публикуется из-за служебных полей формы и трекеров. SHA256 связывает проекции с полученными ответами; сырые ответы остались только во временном локальном каталоге и не нужны для offline-проверки проекций.

Сравнены все CategoryID, VariantID, RateID, цены, валюта, исходная видимость, применимость к запросу, data-available и options. `NormalizeCategoryStock()` вернул 24 наблюдения `known`, 0 `unknown`, 0 `conflict`. Свёрнутые элементы не отброшены нормализатором: учитываются существующие правила `MatchesAdults()` и признаки доступности. Раскрытие интерфейса отдельно подтверждено для ноябрьских ответов. Признаки закрытия продаж, отключённые select и подтверждённое отсутствие мест на выбранных датах не встретились: эти ветки live-проверкой не подтверждены.

Изучены существующие Bnovo-парсер/клиент, нормализация и проверка ожидаемых категорий, модель конфигурации и `configs/arena33.json`. Технической несовместимости в шести ответах не обнаружено; воспроизводимого примера дефекта нет. Следующий этап может использовать существующий источник `bnovo` и точные отдельные RoomType ID. Неизвестный фонд в текущей конфигурационной модели допускается как `total_rooms=null`; подставлять максимальный увиденный публичный остаток вместо фонда нельзя. `rates[].enabled` сейчас используется как allowlist TravelLine: нельзя обещать аналогичную фильтрацию корпоративного тарифа Bnovo только добавлением этого поля в конфиг.

## Что осталось неизвестным

- Актуальная ссылка/iframe основного сайта Теты; работоспособность его кандидата не снимает этот пробел.
- Третье онлайн-место Teta Premium: Bnovo и старый сайт подтверждают только двоих, а заявленное место по запросу не проверялось.
- Физический фонд отелей/категорий, фактическая занятость и возможное пересечение физического фонда двух объектов. В просмотренных публичных данных нет подтверждённого общего количества физических номеров. Публичный остаток — ограниченный сигнал продажи на конкретный сценарий.
- Однозначные условия отмены `751387` и отсутствие специальных требований у `777998`. Для основного сравнения цен корпоративный тариф пока считать непроверенным; питание учитывать отдельно.
- Доступность других дат, составов гостей и LOS; финальная возможность оформить бронирование без дополнительных условий. Никаких заказов, корзин, оплат, обращений к администраторам не было.

Технически обе формы читаются существующим адаптером. Подключение отелей остаётся отдельной задачей: для Теты сначала подтвердить актуальную привязку нового сайта; не объединять объекты или категории и не изобретать фонд.
