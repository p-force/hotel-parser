# Changelog

Все значимые изменения проекта документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
Версии проекта следуют [Semantic Versioning](https://semver.org/spec/v2.0.0.html)
в формате `MAJOR.MINOR.PATCH`. На этапе первоначальной разработки используются
версии `0.y.z`; публичный API пока не считается стабильным.

## [Unreleased]

### Removed

- Legacy-путь `CollectPropertiesStored`, DTO `StoredBatch` и неиспользуемые
  операции `MarkRunning`/`CancelPending`. Сбор и тесты истории используют
  существующий lease-aware runtime `RunQueued` / `RunGroups` (#43).

### Fixed

- Синхронизированы конкурентные проверки pinned PostgreSQL runner lock: workers
  больше не пересекают query/Scan на одном pgx-соединении. Устранена зависимость
  integration warm-up от сохранённой rate-limit истории mock origin.

- TravelLine-категории `kind=apartment` Петровского дворца больше не отклоняют
  весь ответ; площади и предложения сохраняются наравне с `room`.

- Новые CSV на Яндекс Диске используют путь `<root>/<group>/<property>/<слот МСК>.csv`;
  ранее сохранённые пути доставки остаются неизменными.

- Изоляция TravelLine client cache по source property ID и тарифной политике;
  проверка валюты до storage, безопасный mixed Bnovo/TravelLine runtime и сохранение
  исходных квот предложений в nullable `reported_quantity` (миграция 0004).
  Сохранены Bnovo HTML-признаки и хеши идемпотентности старых попыток (#45).

- Подтверждённая публичная недоступность Bnovo на точные даты сохраняется как
  `no_offers` / `known=0` без `$plansForJs`; предупреждение о тарифных метаданных
  относится к затронутым категориям, неоднозначные ответы остаются неопределёнными (#37).

- Общий Bnovo rate limiter перед базовым HTTP transport: задержки проверки lease
  больше не сближают старты запросов. Интервал применяется к разным клиентам,
  retry и redirects, с отменой ожидания и сохранением конкурентности (#36).

### Added

- Пять TravelLine-конкурентов в группе Arena33: полные каталоги категорий,
  проверенные публичные тарифы, fixture/PostgreSQL-тесты и ограниченный live smoke.

- Автоматическая доставка CSV завершённых runs на Яндекс Диск: потоковый экспорт
  PostgreSQL, durable retries и lease/fencing (миграция 0005), проверка checksum,
  восстановление без локального файла и повторных запросов к отелям (#51).

- Автоматический CSV конкретного terminal run после завершения workers: потоковое
  чтение PostgreSQL, атомарная публикация, восстановление отсутствующих файлов
  после restart, отдельные статусы готовности/повтора и writer API для будущей доставки (#49).

- Публичный TravelLine-адаптер AZIMUT Аэростар: категории, цены и квоты через
  существующую PostgreSQL-очередь, отдельные процессные лимиты, исключение BONUS,
  консервативная нормализация, fixture/HTTP/queue-тесты и ограниченный live smoke (#45).

- Регулярные планы 61/8/8/1 для независимых групп PostgreSQL-схем, атомарная
  идемпотентная публикация слотов, fair runner, CLI/защищённый HTTP-trigger,
  восстановление внешними повторными запусками и singleton-защита Bnovo (#27).

- Платформонезависимый runtime PostgreSQL-очереди: execution deadline, heartbeat,
  общий shutdown/flush budget, durable progress и восстановление после отмены (#24).

- Атомарный PostgreSQL claim, продлеваемые аренды и fencing token, восстановление
  заданий после сбоя, ограниченные retry и идемпотентное завершение (#26).

- PostgreSQL storage в отдельной схеме: run/job/attempt и append-only наблюдения,
  идемпотентная транзакционная запись, история всех retry и интеграционные тесты
  на существующем локальном Docker PostgreSQL (#25).

- Процессные лимиты по отелю и источнику, round-robin между отелями,
  source rate limiting и ограниченные retry с jitter/Retry-After. Добавлены
  метрики ожидания, throttling и повторов; существующий пул сохранён (#23).

- Сбор нескольких отелей через общий bounded worker pool с процессным лимитом
  конкурентности (по умолчанию 8), сохранением идентичности результатов,
  отменой очереди и метриками общей активности и исходов по отелям (#22).

- Сценарии Bnovo для 1/2 взрослых: `--adults` в `inventory-check`, скаляр/список
  в конфигурации и пакетный запуск комбинаций взрослых × LOS. Объединение
  наблюдений сохраняет сценарии и расхождения без суммирования остатков.

- Пакетный Bnovo-сбор через ограниченный worker pool (по умолчанию 3), с интервалом
  стартов, сохранением порядка, отменой context и метриками очереди и исходов пакета.

- Базовый Go-модуль `github.com/p-force/hotel-parser` и точка входа приложения
  с сообщением о запуске.
- Логгер на основе `log/slog` с уровнями сообщений, временем, атрибутами
  и вложенными группами; регрессионный тест группировки атрибутов.
- Многоэтапная Docker-сборка приложения и Docker Compose для локального
  PostgreSQL 17 с постоянным томом данных.
- Пример переменных окружения для подключения к PostgreSQL, таймаута выполнения
  и параметров Bnovo для Arena33.
- Команды Makefile для запуска, сборки, форматирования, статического анализа,
  тестирования и управления зависимостями.
- GitHub Actions CI с проверкой форматирования, `go vet`, тестами с детектором
  гонок и сборкой; версия Go определяется из `go.mod`, зависимости кешируются.
- README с описанием проекта и инструкциями по локальному запуску,
  а также правила исключения служебных файлов для Git и Docker.
- Пакет `internal/config` с моделями конфигурации отеля, источника данных,
  номерного фонда и параметров сбора.
- Загрузка конфигурации из JSON-файла с отклонением неизвестных полей
  и лишних данных после JSON-документа.
- Валидация обязательных полей, часового пояса, HTTPS-адреса источника,
  уникальности категорий и соответствия общего числа номеров сумме категорий.
- Проверка параметров сбора Arena33: два взрослых без детей, один номер,
  положительный горизонт поиска и длительности проживания 1, 2 и 3 ночи.
- Конфигурация `configs/arena33.json` для Arena33 с источником Bnovo,
  19 номерами в трёх категориях и горизонтом поиска 60 дней.
- Тесты загрузки конфигурации Arena33 и валидации её параметров.
- Адаптер Bnovo: модели поиска, категорий, вариантов размещения, тарифов
  и публичных признаков доступности.
- HTTP-клиент Bnovo с таймаутом 20 секунд, лимитом ответа 8 МиБ
  и ограничением редиректов исходным origin и тремя переходами.
- HTML-парсер категорий, тарифов, цен за весь период и условий бронирования.
- Метод `Client.Collect(ctx, req)` с единым результатом для успешных и неудачных
  попыток, HTTP-метаданными и классифицированными ошибками.
- Диагностический CLI `cmd/bnovo-check` со сводкой и JSON-результатом.
- Отдельная проверка ожидаемых категорий по конфигурации в `internal/collect`.
- Тесты HTTP-клиента, парсера и сбора на локальных HTTP-серверах и HTML-фикстурах.
- Структурированные события Bnovo-сбора с `attempt_id`, параметрами поиска,
  HTTP-статусом, счётчиками и кодами ошибок без содержимого ответов.
- Настройка формата и уровня логов через `HOTEL_PARSER_LOG_FORMAT`
  и `HOTEL_PARSER_LOG_LEVEL`; JSON по умолчанию в Docker.
- Метрики HTTP, парсинга и всей попытки в итоговых логах, с UTC-временем начала
  и отсутствием длительности у невыполненных этапов.
- Формат сводки пакета: `batch_duration_ms` и счётчики исходов без очереди и worker pool.

### Changed

- Компактное текстовое представление событий Bnovo в `PrettyHandler`;
  JSON сохраняет все атрибуты, сводка и полный JSON диагностического CLI сохранены.
- На INFO остаётся одна итоговая запись сбора; этапы перенесены на DEBUG.
  Убраны пустые коды ошибок, повторение контекста и универсальный `duration_ms`.

- Команда `make check` проверяет форматирование без изменения файлов,
  запускает статический анализ, тесты с детектором гонок и сборку.
- CI запускается при push и pull request для веток `dev` и `master`.
- Требуемая версия Go повышена до 1.26; добавлен `golang.org/x/net/html`.
- Сохранён текстовый формат `PrettyHandler`: `[LEVEL] YYYY-MM-DD HH:MM:SS message key=value`.
  JSON использует `slog.JSONHandler`; логи идут в stderr отдельно от результата CLI в stdout.

### Fixed

- Варианты Bnovo с большим числом значков гостей учитываются для меньшего запроса
  при явном подтверждении тарифной строки `tr[data-available="1"]`. Цены сценариев
  сохраняются отдельно; отсутствие подходящего одноместного варианта не даёт ноль.

- Свёрнутые предложения Bnovo больше не считаются недоступными только из-за
  `Visible=false`: парсер и нормализация проверяют бронируемость и число гостей.

- Начало HTTP-этапа отмечается явно через `HTTPResponse.RequestStarted`,
  независимо от измеренной длительности.
- HTTP-duration считается по монотонным часам и включает чтение ответа;
  неотправленные запросы не получают фиктивную длительность.
- Удалён суффикс `.git` из пути Go-модуля: локальные импорты корректно разрешаются.
- Ранее привязанные атрибуты логгера сохраняют свою группу при добавлении
  вложенных групп.
- В финальный Docker-образ добавлена `tzdata` для загрузки `Europe/Moscow`.
- При ошибке загрузки `Europe/Moscow` логгер использует UTC+3 и выводит
  предупреждение с причиной ошибки.
- Неизвестная доступность категории приводит к `partial`; недоступность
  подтверждается только для корректных дат, совпадающих с запросом.
- Страницы без обязательной структуры Bnovo возвращают ошибку парсинга;
  распознаваемые неполные данные сохраняются со статусом `partial`.
- Предложения с одинаковым ключом и противоречивыми данными исключаются целиком
  с предупреждением; идентичные дубликаты объединяются.
