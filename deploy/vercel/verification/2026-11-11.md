## Реализация

- Новый защищённый `/api/start`: только наступивший08:00МСК текущего дня; до08:00 — `slot_not_due`. Задержанный Cron не переключается на12/16/20 и не восстанавливает прошлые дни.
- Новый action существующего `schedule.Service`: session runner lock → публикация всех `PlanRun` → commit → прежний `RunGroups`. При ошибке любого плана HTTP не запускается. Уже опубликованная часть идемпотентно восстанавливается повтором.
- Claim `/start` фильтруется точным `collection_runs.started_at`, старые slots не расходуют пачку. `/resume`: новые slots раньше старых внутри каждого отеля, прежняя fairness групп/отелей. Активный прежний runner не прерывается, второй получает409.
- Claim/lease/fencing/retry/source gates сохранены, новых таблиц и очередей нет. Действующий FIFO остаётся default для callers без новых опций. Схема БД и source adapters не меняются.
- В JSON добавлен `summary` durable результатов: planned/completed/remaining jobs слота для start, всей очереди для resume. Это не количество HTTP и не число успешных claim текущего вызова. При неизвестном progress — `null`, а не фиктивные нули.
- После workers/runner lock используются прежние CSV и delivery. Если budget закончился, следующий resume восстанавливает финализацию/доставку из PostgreSQL. Никаких self-invocation или фоновой работы после HTTP-ответа.

## Cron и включение сбора

Подготовлен [cron.example.json](../cron.example.json): ровно `/api/start`, `0 5 * * *`. Корневой `vercel.json` не содержит `crons`, definitions проекта пока пусты: **Cron не активирован**. `CRON_SECRET` в Production отсутствует; production-секреты не создавались/не заменялись. `HOTEL_PARSER_COLLECTION_ENABLED=false` сохранён и проверен read-only health. Только MaxJobs изменён на64.

Для отдельной активации: настроить CRON_SECRET в Dashboard, подтвердить отсутствие второго collector, перенести единственную crons-секцию в корневой конфиг и осознанно включить collection. Это создаст366утренних jobs, но один вызов обработает максимум64. Встроенного автоматического продолжения раз в минуту на Hobby нет; нужен отдельно согласованный способ resume. Точность08:00 не гарантируется: дневной Hobby Cron может прийти08:00–08:59МСК.

Документация: [duration](https://vercel.com/docs/functions/configuring-functions/duration), [Go runtime](https://vercel.com/docs/functions/runtimes/go), [Cron Hobby](https://vercel.com/docs/cron-jobs/usage-and-pricing). Для Go HTTP-server preset используется project default, неподдерживаемый glob на `cmd/api/main.go` не добавлен.
